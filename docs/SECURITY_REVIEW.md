# Security review

Reviewed trust boundaries include employee API access, provider ingestion, browser cookies, file parsing, export generation, stock mutation and external messaging. This is an implementation review, not a certification or legal compliance opinion.

## Production responsibilities

Profile/chat uploads use a dedicated PostgreSQL byte table with size/kind constraints. Retrieval requires authentication and message-participant/channel access; only owners remove message files. Uploads validate extension/signature and enforce 512 KB photos, 2 MB attachments and a serialised 10 MB message quota per employee. No public upload directory or filesystem persistence is used. This is bounded demo storage, not malware scanning; production document sharing needs scanning and object storage. The free-demo bootstrap rejects unmarked business databases and keeps existing credentials on restart.

Employee workspace additions enforce owner-only workbook access, participant-only direct-message queries and assignee/manager task updates. Profile updates cannot change role or login identity. Workbook exports validate source indices on the server, audit downloads and neutralise formulas. No workbook formulas or macros execute. Integration tests cover private workbook access, private conversations, task ownership and competing warehouse packers.

Use HTTPS, encrypted database/backups, secret-manager injection, separate migration owner and restricted runtime DB user. Restrict direct API/database network exposure. Register and approve production SMS/WhatsApp templates and complete privacy governance with the organisation. The implementation does not guarantee statutory compliance by itself. The database owner can alter/drop immutability triggers; stronger independent audit assurance requires an external append-only sink and restricted administrator access.

Rate limits are process-local. Deploy a single API instance as provided; a multi-instance deployment needs a shared rate-limit store or ingress enforcement. SMTP and messaging failures require monitoring. Set retention according to approved business and privacy policy. Validate provider delivery using real credentials before cutover. Do not publish LOCAL_ACCESS.md or any .env files.
